# voicectl — Jev を使った Windows 音声操作アプリ

F5 キーを押しながら話すと、PC を声で操作できます。
「メモ帳開いて」「もうちょい右」「そこクリック」「保存押して」「番号表示」→「5番」のような話し言葉に対応します。

## 起動

1. API キーを環境変数に登録する（初回のみ。登録後はターミナルやアプリを開き直す）
   ```
   setx TYPESAFE_API_KEY "<APIキー>"
   ```
2. `run.bat` をダブルクリックする。トレイにマイクのアイコンが出て、画面右下に状態が表示されます
   - Jev を使わずに試す: `run.bat --keyword-only`
   - 詳しいログを出す: `.venv\Scripts\python.exe -m voicectl --debug`

## ブラウザをマイクにする（リモート接続中に使う）

Windows App（リモートデスクトップ）で接続していると、PC 本体のマイクは使えません。
Windows 11 Home では、接続元のマイク転送も動かないことがあります。その場合は、接続元の Mac や iPhone のブラウザをマイクにします。

1. トレイアイコンを右クリック →「ブラウザマイクの URL をコピー」→ アドレスを選ぶ
   - 同じ LAN なら `192.168.…`、外出先なら Tailscale の `100.…`
2. Mac や iPhone のブラウザで、その URL を開く
   - 初回は自己署名証明書の警告が出るので、「詳細」から「このWebサイトを閲覧」を選ぶ
   - マイクの使用を許可する
3. 大きなボタン（Mac ではスペースキー）を押している間に話す。認識結果と実行した操作は、ページにも表示されます

URL には合言葉（トークン）が付いていて、これがないとページを開けません。
合言葉を変えたいときは `cache/remote_mic_token.txt` を削除してアプリを再起動してください。

## 操作

| 操作 | 方法 |
|---|---|
| 話す | **F5 キーを押している間**だけ聞き取ります |
| ハンズフリー | 待機中に**「コンピューター」と声をかける**と聞き取りが始まります（話すたびに実行し、
  12 秒言葉がなければ自動で待機に戻る。「コンピューター、音量30」のように一言に続けて言っても動きます。
  トレイの「ウェイクワードで開始」でオン・オフ） |
| 常時聞き取り | **F5 を短くタップ**すると話すたびに実行（もう一度タップで終了） |
| 緊急停止 | **Pause キー**、または「ストップ」と言う（確認待ち・番号表示・ドラッグ中のボタンをすべて解除） |
| 確認に答える | 「はい」か Enter で実行、「いいえ」か Esc で取消（8 秒で自動取消） |
| 一時停止・終了 | トレイアイコンを右クリック |

### 話し方の例

- アプリ: 「メモ帳開いて」「ブラウザ起動」「Chrome に切り替え」
- Web サイト: 「YouTube 開いて」「ネットフリックスで鬼滅の刃を探して」「楽天で掃除機を検索」
- フォルダ: 「ダウンロード開いて」「ドキュメントフォルダ」「ごみ箱を見せて」
- マウス: 「右」「もうちょい上」「左下に大きく」「もっと」（前回と同じ方向）
- クリック: 「クリック」「右クリック」「ダブルクリック」「保存押して」「OK をクリック」
- 画面上の物が名前で押せないとき: 「番号表示」→「5番」、または「グリッド」→「5」→「2」→「クリック」
- スクロール: 「下にスクロール」「上にちょっとスクロール」
- キー: 「コピー」「貼り付け」「元に戻す」「エンター」「新しいタブ」「音量上げて」
  「音楽止めて」「音楽流して」（再生・一時停止）、「次のウィンドウ」「前のウィンドウ」（Alt+Esc）
  「画面を撮って」（全画面を画像に保存）、「切り取って」（範囲を選んで切り取り）
- ブラウザ: 「アドレスバー」「ブックマーク」「履歴を見せて」「ダウンロード一覧」「閉じたタブを開き直して」
  「名前を付けて保存」「印刷」「フルスクリーン」「開発者ツール」「シークレットウィンドウ」
  「強制再読み込み」「検索して置換」「ページの先頭に戻って」
- ウィンドウ: 「右半分にして」「左のモニターへ移して」「画面いっぱいにして」（「ウィンドウを左に寄せて」も可。
  「左に寄せて」だけはマウス移動になります）「常に手前にして」（解除は「常に手前を解除」）
  「上半分に」「下半分に」「中央に置いて」「左上に置いて」「右上の四分の一」（マウス移動の「左上」と区別するため、
  四分の 1 は「置いて」を付けます）
- Windows: 「パソコンをロック」「タスクマネージャー開いて」「エクスプローラー」「クリップボードの履歴」
  「Windows の設定」「通知を開いて」「音声入力」「絵文字パネル」「新しいデスクトップ」「次のデスクトップ」
- 入力: 「こんにちはと入力」「明日の会議って打って」（入力は必ず確認が入ります）
- その他: 「もう一回」「最小化」「デスクトップ」
- 特定のアプリの操作: 動画（YouTube・VLC）「字幕つけて」「シアターモード」「次の動画」、
  メモ帳「折り返し」「時刻と日付」、エクスプローラー「新しいフォルダ」「名前を変更」「上の階層へ」「選択して開いて」、
  VS Code「コマンドパレット」「ターミナル」「すべて保存」など（`profiles/` に定義）
- 入っていないアプリ・サイト: 「Notion開いて」「Xというサイト開いて」「ヨドバシの公式サイト開いて」
  （デスクトップ版がインストール済みならアプリを起動。名前だけのサイトは一番目の検索結果を開く）
- 言い直し: 「〇〇開いて」のあと 45 秒以内に「アプリはObsidianです」「Xです」→ 正しい名前で開き直す

### 手順を覚えさせる（ルーチン）

| 言い方 | 動き |
|---|---|
| 「作業開始と言ったらObsidianを開いてChromeを開いて」 | 声でルーチンを登録。以後「作業開始」で順に実行 |
| 「ログインの手順を記録して」→ 実際に操作 →「記録終了」 | やって見せたクリックと声の命令を記録（キー入力は記録しない）。「ログイン」で再生。クリックは UI Automation で要素を探し直すので位置がずれても当たる |
| エージェントが成功した直後に「これ覚えて」 | その手順を目的の言い方で保存。次からは Jev に 1 手ずつ聞かずに即再生 |
| 「ルーチン一覧」「〇〇のルーチン消して」「記録取り消し」 | 確認・削除・破棄 |

`config.yaml` の `routines:` に書いても登録できます。声で登録したものは `state/routines.json` に入ります。
同じ流れを 3 分以内に続けて 3 回言うと「この流れ、よく使っていますね」と提案が出ます。「〇〇として登録」で一言にまとまります。

### AI アシスト（DeepSeek・opencode 経由）

答えは右下の「答えカード」にタイプするように表示し、質問・要約・振り返りは声でも読み上げます。
考えている間（3〜6 秒）も次の命令は聞き取れます。

| 言い方 | 動き |
|---|---|
| 「来週の打ち合わせのお礼メールを書いて」 | 下書きを作って表示 →「入力して」で前面の入力欄へ／「もっと短く」「敬語で」「英語で」で直す／「いらない」で捨てる |
| 文字を選んで「これを英語にして」「丁寧にして」「短くして」「箇条書きにして」「直して」 | 選択中の文字を書き直して置き換える（「元に戻して」で戻せる） |
| 文字を選んで「要約して」「これの意味を教えて」「これに返信を書いて」 | 要約・説明を表示／返信は下書きとして表示 |
| 「この画面を要約して」「この画面で何ができる？」「ここ何て書いてある？」 | 前面のウィンドウの文字を読んで答える |
| 「量子コンピュータって何？」「〇〇について教えて」 | 質問に答える |
| 「今日何した？」 | 今日の操作の記録から振り返る |

Jev で決まらなかった言い方も DeepSeek が「アプリがそのまま実行できる言い方」に言い直します
（「明日の朝7時に目覚ましかけといて」→「7時に起こして」、「ボリュームを三割くらいに」→「音量30」）。
依頼の文と対象の文字は DeepSeek に送られます。止めるときは `assistant.enabled` と `decision.llm_fallback.enabled` を false に。

### 続きからの指示

一度に言い切らなくても、前の続きから操作できます。直前に扱ったものは覚えているので、言い直す必要はありません。

| 言い方 | 動き |
|---|---|
| 「続き」「残りをやって」 | 複数手順のうち、失敗・中断した手順からやり直す（LLM の手順でも「〇〇して△△して」の分け実行でも同じ） |
| 「さっきのページ」「その動画を開いて」 | 直前に開いた URL（無ければサイト＋検索語）をもう一度開く |
| 「さっきのアプリ」「そのウィンドウに戻して」 | 直前に使ったアプリを前面に出す |
| 「さっきのやつをもう一回」「もう一回」 | 直前の命令（複数手順なら手順全体）をもう一度 |
| 「これ覚えて」 | 直前の操作を覚える（次からは確認なしで同じ言い方が通じます） |
| 「忘れて」 | 直前に学習で実行した言い方を忘れる |
| 「何覚えてる？」 | 覚えている言い方と成功回数を表示する |

複数手順の途中で 1 手が失敗しても、残りの手順は続けて実行します（失敗した手順だけを知らせ、「続き」で再開）。
Pause キーで中断したときも、残りは「続き」で再開できます（5 分以内）。
アプリの起動待ちなどで一時的に操作が届かないときは 1 回だけ自動で試し直し、ボタンのクリックが届かないときは
座標クリックに切り替えます。

## 仕組み

```
F5押下 ─┬─ 録音開始（押す直前 0.3 秒も含む）
            └─ 画面情報の先読み：前面ウィンドウ・カーソル位置・UI Automation・OCR・Windows の状況
                （窓の種類・ダイアログとそのボタン・フォーカス・エクスプローラーのフォルダと選択も話している間に取る）
F5離す ── STT（faster-whisper large-v3-turbo / RTX 4080）
           ── 「ストップ」「はい/いいえ」「番号」「これ覚えて／忘れて」はここで即処理
           ── 続きの指示（「続き」「さっきのページ」「そのアプリ」）は文脈から即実行
           ── 高速経路：定型の短い命令（「右」「クリック」「右半分にして」等）は画面の収集を待たずに即実行
           ── 話している最中の認識（文字起こしバー）がほぼ全体をカバーしていれば、離したときの再認識を省く
           ── タスクひな形：サイトを開く・検索する・フォルダを開く（tasks.py）も LLM なしで実行
           ── 前に覚えた言い方（learner.py）は、Jev も LLM も通さずそのまま実行
           ── それ以外は Jev に 1 回問い合わせ（全質問を並列評価）
                 action / app / window / element / direction / amount / button / key / snap / … / is_continuation
           ── 確信度 0.80 以上: 実行 ／ 0.50〜0.80・危険な操作: 確認 ／ 0.50 未満: 聞き返し
           ── それでも決まらないときだけ LLM に 1 回問い直す（既定はローカルの Ternary Bonsai 2 27B）
                 複合命令の分解（plan）・入力文字列の生成・聞き返し文の生成。長い発話もここで拾う
           ── 最後の砦: Jev に 1 手ずつ選ばせて進める多段エージェント
```

上の 3 段（続きの指示・キーワード照合・タスクひな形）と学習した言い方は通信も LLM も使わずに決まるため、
日常的な言い方はここで処理され、LLM の出番は残りわずかになります（`logs/decisions-*.jsonl` の
`engine` で確認できます）。

### 覚えて育つ（学習）

一度解釈できた言い方は `state/learned.json` に貯まり、次からは Jev も LLM も通さずに実行します。

- 覚えるきっかけ: LLM が解釈できたとき／確認に「はい」と答えたとき／「これ覚えて」と言ったとき。
- 表記が揺れても、読みの骨格（`phonetic.ja_skeleton`）で照合するので「トレーナー」と「とれーなー」は同じ扱いです。
- 3 回成功した言い方は**確認なしで実行**に昇格します。失敗が成功を上回ると忘れます。
- アプリごとに覚えた言い方は、そのアプリのときだけ使います（「これ押して」のような言い方が他アプリで誤爆しません）。
- 「何覚えてる？」で一覧、「忘れて」で取り消し。`state/learned_suggestions.md` に、固定の規則
  （`keyword.py` / `profiles/*.yaml`）へ移すとよい候補が書き出されます。

- **Jev は画像を見られない**ため、画面の中身は UI Automation（ボタン名と座標）と Windows 標準 OCR（文字と座標）で
  テキストにし、Jev には「どの要素か」を選択肢から選ばせます。どちらでも取れない画面は番号グリッドで操作します。
- **Jev は自由テキストを返せない**ため、「〜と入力」の文字列だけはルールで切り出します（`textparse.extract_text`）。
- 音声認識の表記ゆれには読みで照合します（`textparse` / `phonetic`）:
  長音の「おー / おお / おう」、ひらがな・カタカナ・漢字の違い（「さくじょ」/「削除」）、漢字の同音異義は、
  かなに揃えて長音を畳み、さらに pykakasi で読み（カタカナ）に直して比べるため、辞書や画面のボタン名の
  表記と一致しなくても見つかります。
- Jev の呼び出しに失敗したときは、キーワード照合で代わりに判定します（`decision.fallback_to_keyword`）。

## 設定ウィンドウ

トレイアイコンの右クリック →「設定」で開きます（config.yaml を読み書きします。CLI からの編集とも共存）。

| タブ | 内容 |
|---|---|
| マイク・キー | 話しかけキー・緊急停止キー、マイクの選択と「テスト」録音（レベル表示）、途切れ実行のオンオフ |
| 判定 | 実行・確認のしきい値スライダー、LLM 言い直し・文章アシスタント・読み上げ・アラーム連携・ウェイクワードのオンオフ |
| 窓と配置 | 配置のひな形（layouts）の表エディタ、マウス移動量・スクロール量、ファイル検索の追加場所 |
| 覚えたもの | 学習した言い方の一覧と削除（すぐ反映）、ルーチンの一覧と削除（すぐ反映） |
| 連携 | Jev の API キーを環境変数に登録（マスク入力。キーはファイルやログに書きません） |

「保存して再起動」で voicectl が再起動して設定が反映されます（学習とルーチンの削除以外は再起動が必要です）。

## 配布について

配布を始めるにあたっての現状の前提（`requirements.txt` はこの環境で動作確認済みの組み合わせ）:

- **OS / ハード**: Windows 11 + NVIDIA GPU（音声認識を GPU で行います。RTX 4080 で動作確認。GPU のない PC は CPU 構成の検討が必要）
- **Python**: 3.12（`python -m venv .venv` → `.venv\Scripts\pip install -r requirements.txt`）
- **API キー**: `TYPESAFE_API_KEY`（Jev 用）。設定ウィンドウの「連携」タブから環境変数に登録できます
- **音声の行き先**: 認識はこの PC 内（faster-whisper）、判定は Jev へ、文章の作成は DeepSeek へ送られます。設定ウィンドウの「連携」タブにも表示されます
- **残る作業**: インストーラー化（単一 exe か同梱フォルダか）、GPU のない PC への CPU フォールバック、初回ウィザード、設定のバージョン移行（`config.yaml` の `version` を使用）

## config.yaml の項目（設定ウィンドウにない細かい設定）

`config.yaml` を編集します。主な項目:

- `hotkeys.push_to_talk` / `hotkeys.emergency_stop`: キーの変更（`right_ctrl`, `f13`, `scroll_lock` など）
- `wake_word`: ハンズフリー（待機中の呼びかけ）。`words` で呼びかける言葉を変えられ
  （例: `["ヘイパソコン"]`）。反応が悪いときは `level`（話し声とみなす音量）を下げる。
  周りの音で確認が増えすぎるときは `min_interval_sec` を上げる
- `audio.device`: マイク名の一部（例 `"Seiren"`）。既定のマイクがない場合は名前に「マイク」を含むものを自動で選びます
- `dictionary`: 読み替え辞書（カタカナ → 英語表記など）。読みは認識結果と長音の表記（おー/おお/おう）が
  違っても、かなの種類（ひらがな・カタカナ）が違っても置き換えられます。1 文字の聞き間違いも
  「近い読みの辞書語」に置き換わります（4 文字以上）
- `vocabulary`: 音声認識に覚えさせたい固有名詞・専門用語（聞き間違いやすい単語を足していく）。
  漢字の選ばれ方が変なときは、正しい表記の単語を足すと認識が安定します
- `thresholds`: 実行・確認の確信度のしきい値
- `always_confirm`: 必ず確認する操作
- `app_aliases`: アプリの呼び方（例: `"Google Chrome": [ブラウザ, クローム]`）
- `mouse.step_px`: 「少し / 普通 / 大きく」の移動量
- `decision.llm_fallback`: LLM の問い合わせ先。既定はローカル（`backend: local` / `local.base_url` は
  この PC のみ指定可）。`backend: opencode` にすると opencode 経由（DeepSeek など）でも呼べます。
  `cooldown_sec` は続けて失敗したときに休む秒数（そのあと自動で再開します）
- `learning`: 覚える仕組み（`enabled` / `trust_at`（確認なしに昇格する成功回数）/ `fuzzy`（読みの近さ）/
  `max_entries`）。`state/learned.json` に保存され、消したいときはファイルを削除するか「忘れて」と言います
- `overlay`: 状態表示の位置（`corner`）・文字の大きさ（`font_px`）・余白（`margin_px`）・
  タスクバーを避けるか（`avoid_taskbar`）・アニメーション（`animate`）

判定の記録は `logs/decisions-YYYYMMDD.jsonl` に残ります（発話・判定・確信度・処理時間）。しきい値の調整に使えます。

## テスト

```
.venv\Scripts\python.exe -m pytest tests -q          # ロジックのテスト（実機操作なし）
.venv\Scripts\python.exe tests\smoke_commands.py     # 追加した言い方の通し確認（操作はしない）
.venv\Scripts\python.exe tests\overlay_check.py      # 表示がタスクバーに隠れないか（offscreen で確認）
.venv\Scripts\python.exe tests\stt_check.py          # 合成音声で STT を確認
.venv\Scripts\python.exe tests\pipeline_check.py     # 合成音声で判定までを通す（操作はしない）
```

`smoke_commands.py` は、高速経路（「右半分にして」など）・サイト／フォルダ・続きの指示・プロファイルの
ショートカット・確認表示をまとめて点検します。プロファイルを編集したあとに走らせると、キーの書き間違いに
気づけます（例: `Ctrl+H` を `Ctr+H` と書いていれば NG になります）。

## 既知の制約

- Jev（公式 API）は 2026 年 9 月時点でアーリーアクセスです。
- 実測の遅延（話し終わってから実行まで）：定型の命令（高速経路）は約 0.35 秒、Jev を通す命令は約 0.6 秒
  （STT 約 350 ms ＋ Jev 約 200〜300 ms）。STT は発話の長さに関係なくほぼ一定です（4080 の場合）。
- LLM フォールバックは既定でローカルの `llama-server`（Ternary Bonsai 2 27B）を使います。**サーバを
  起動していないときは LLM の段だけが働きません**（判定・実行は Jev とキーワードで動き続けます）。
  起動コマンドは `D:\llama.cpp-bonsai\...` のバッチ、または `llama-server -m <重み> --alias bonsai2-27b
  --port 8080 --ctx-size 65536` です。3 回失敗すると 90 秒休み、そのあと自動で再試行します。
- 「右上のバツ押して」のように、位置と記号で指す言い方は確信度が低く、聞き返しになりやすいです。
  その場合は「閉じるボタン押して」のように名前で言うか、「番号表示」を使ってください。
- Chromium 系や Electron のアプリは、UI Automation ではタイトルバー付近しか取れないことがあります（OCR で補完）。
- 管理者権限で動いているアプリは、このアプリも管理者として起動しないと操作できません（Windows の仕様）。
